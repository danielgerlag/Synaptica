## TOP 5 CRITICAL ISSUES TO FIX IMMEDIATELY

### 1. PATH TRAVERSAL VULNERABILITY (CRITICAL)
- **File**: C:\dev\Synaptica\crates\synaptica-server\src\main.rs
- **Lines**: 167-172
- **Issue**: No path normalization in static file serving
- **Exploit**: GET /../../../etc/passwd serves arbitrary files outside base directory
- **Fix**: Use path canonicalization and validate within base directory

### 2. METRICS PANIC ON STARTUP (CRITICAL)
- **File**: C:\dev\Synaptica\crates\synaptica-server\src\metrics.rs
- **Lines**: 12, 20, 22, 25, 32-44
- **Issue**: Multiple .unwrap() calls on Prometheus registration
- **Impact**: Application crashes if metrics misconfigured
- **Fix**: Properly handle registration errors with Result<>

### 3. DISTRIBUTED TRANSACTION STATE LOGIC ERROR (CRITICAL)
- **File**: C:\dev\Synaptica\crates\synaptica-cluster\src\distributed_tx.rs
- **Lines**: 293-301
- **Issue**: Transaction stays in "Preparing" state after participant votes NO
- **Impact**: Can call commit on transaction that should be aborted
- **Fix**: Transition to Aborted state immediately on NO vote

### 4. SILENT WAL PERSISTENCE FAILURES (CRITICAL)
- **File**: C:\dev\Synaptica\crates\synaptica-cluster\src\distributed_tx.rs
- **Lines**: 137-154
- **Issue**: WAL write errors silently ignored
- **Impact**: Recovery impossible after coordinator crash
- **Fix**: Return Result<> from persist_entry() and handle errors

### 5. MUTEX POISON PANICS IN 2PC (CRITICAL)
- **File**: C:\dev\Synaptica\crates\synaptica-cluster\src\distributed_tx.rs
- **Lines**: 229, 254, 269, 310, 337, 348, 373+
- **Issue**: .lock().unwrap() throughout; panics if any thread panics with lock held
- **Impact**: Distributed transaction coordinator can crash
- **Fix**: Use error handling or parking_lot::Mutex

## CONCURRENCY PROBLEMS

### Identified Race Conditions:
1. **WAL Logging Lock Hold Duration** (distributed_tx.rs:268-272)
   - Mutex held during slow I/O to participants
   - Fix: Release lock before participant contact

2. **Semaphore Race on Rejection** (main.rs:146-150)
   - Connection dropped without graceful close
   - Fix: Send HTTP 503 before dropping connection

3. **Nested Mutex Locking Without Timeout** (distributed_tx.rs)
   - Multiple lock acquisitions; no timeout
   - Fix: Add timeout-based locking or use deadlock detection
